## 자기수정이란 무엇인가

AlphaEvolve가 알고리즘을 탐색한다면 Darwin Gödel Machine(DGM)은 에이전트의 도구·작업 흐름을 관리하는 스캐폴드 코드 자체를 탐색한다. 보고된 실험에서 기반 모델의 가중치는 고정되어 있다.

논문은 평가에 사용한 SWE-bench Verified 200개 태스크 부분집합에서 20.0%에서 50.0%로, 전체 Polyglot에서는 14.2%에서 30.7%로 향상됐다고 보고한다. 수치를 인용할 때 태스크 부분집합과 실행 조건을 함께 적는다. Verified 전체 500개 태스크의 리더보드 결과와 같지 않다.

DGM은 수정의 유익함을 형식적으로 증명하지 않고 코딩 결과로 경험적으로 평가한다. 벤치마크 통과가 평가 밖의 안전을 증명하지는 않는다.

## DGM의 자기수정 루프 구조

DGM은 에이전트 변형과 부모·자식 관계를 아카이브에 보존한다. 부모를 선택해 자신의 스캐폴드를 수정하게 하고 새 에이전트를 평가한다. 아카이브에 들어가려면 컴파일과 코드 편집 능력의 기본 조건을 만족해야 한다.

```text
에이전트 변형·평가 결과 아카이브
          |
          v
성능과 탐색 기준으로 부모 선택
          |
          v
부모가 스캐폴드 수정을 제안하고 구현
          |
          v
통제된 환경에서 후보 평가
          |
          v
기본 조건을 만족하는 변형과 계보를 아카이브에 보존
          |
          +----> 다음 부모 선택
```

모든 변형이 부모보다 높은 점수를 얻어야 보존되는 것은 아니다. 낮은 점수의 변형도 나중의 개선을 위한 디딤돌이 된다. 즉시 개선되지 않은 후보를 모두 버리는 절차는 논문의 개방형 탐색이 아니라 탐욕적 언덕 오르기에 해당한다.

## 무엇을 수정하는가: 스캐폴드의 층위

DGM에서 에이전트가 수정하는 것은 **자신이 문제를 풀기 위해 사용하는 스캐폴드 코드**다. 여기에는 여러 층위가 있다.

| 수정 층위 | 예시 |
|---|---|
| 도구 인터페이스 | `bash` 도구의 타임아웃 값, 출력 파싱 방식 |
| 컨텍스트 관리 | 어떤 파일을 먼저 읽을지, 요약 전략 |
| 오류 처리 | 특정 에러 패턴에 대한 재시도 로직 |
| 작업 분해 | 큰 태스크를 어떻게 서브태스크로 나눌지 |
| 검증 전략 | 수정 후 어떤 테스트를 먼저 실행할지 |

에이전트가 이 층위들을 시험하고, 벤치마크로 검증하고, 좋은 변이를 축적한다. 수십~수백 세대를 거치면서 특정 벤치마크에 특화된 스캐폴드가 자동으로 진화한다.

## AlphaEvolve와의 비교

같은 진화적 루프지만 DGM은 **진화의 대상이 다르다**.

```text
┌────────────────────┬──────────────────────┬──────────────────────┐
│                    │    AlphaEvolve        │   Darwin Gödel Machine│
├────────────────────┼──────────────────────┼──────────────────────┤
│ 진화 대상           │ 알고리즘 해법(코드)    │ 에이전트 스캐폴드 코드 │
│ 평가 기준           │ 수학적 성능, 처리량    │ 코딩 벤치마크 통과율  │
│ 집단 구조           │ 명시적 집단 유지       │ 버전 계보 유지        │
│ 변이 단위           │ 단일 알고리즘 코드     │ 에이전트 구성 요소    │
│ 자기참조            │ 없음                  │ 있음 (자신을 수정)    │
└────────────────────┴──────────────────────┴──────────────────────┘
```

AlphaEvolve는 도구(알고리즘)를 만들고, DGM은 도구를 사용하는 **장인(에이전트) 자신**을 개선한다.

## 안전 통제와 평가의 한계

샌드박스·인간 감독·추적 가능한 변경 기록은 실험의 영향 범위를 제한한다. 이 통제는 코딩 점수와 별개다. DGM은 일반적인 안전 보장이나 임의의 자기수정 권한을 제공하지 않는다.

평가 코드·인증 정보·배포 권한은 수정 가능한 스캐폴드 밖에 둔다. 홀드아웃 태스크로 평가하고 도구 실행·정책 변경은 별도로 검토한다. 벤치마크 점수가 높아져도 보상 해킹·과적합·측정 밖의 회귀가 생길 수 있다. 실험 아카이브 보존과 운영 배포에는 다른 승인 기준이 필요하다.

## 루프 엔지니어의 관점

DGM이 보여주는 가장 중요한 통찰은 **루프 자체가 개선의 대상이 될 수 있다**는 것이다. 지금까지의 챕터에서 우리는 루프를 엔지니어가 설계하는 것으로 다뤘다. DGM은 루프가 자신을 설계하는 방향을 가리킨다.

실용적 의미는 두 가지다.

첫째, **메타-루프(meta-loop) 설계**. 내부 루프(문제 해결)와 외부 루프(스캐폴드 개선)를 분리하고, 외부 루프의 검증 기준을 명확히 정의하면 자동 개선의 토대가 생긴다.

둘째, **벤치마크의 중요성**. 자기수정 루프는 검증 기준의 품질에 전적으로 의존한다. 벤치마크가 나쁘면 루프가 잘못된 방향으로 수렴한다. 무엇을 측정할 것인가가 루프의 방향을 결정한다.

다음 챕터에서는 모델 가중치 자체를 루프로 개선하는 GRPO와 DeepSeek-R1을 살펴본다. 스캐폴드가 아니라 **모델 내부**가 루프의 대상이 되는 이야기다.
