## 누구를 위한 사이트인가

- **에이전트를 만들어 본 개발자** — ReAct를 한 번 돌려봤지만 "왜 무한 루프에 빠지는지, 언제 멈춰야 하는지"를 체계적으로 이해하고 싶은 사람
- **프로덕션 에이전트를 운영하는 엔지니어** — 비용 폭증, 컨텍스트 붕괴, 신뢰성 문제를 루프 설계 관점에서 해결하려는 사람
- **AI 시스템 설계자·연구자** — 단일 호출 프롬프팅을 넘어 자율 루프, 멀티 에이전트, 자기개선 루프의 원리와 한계를 깊이 파고들려는 사람

## 콘텐츠 원칙

- **검증 가능한 일차 출처만 인용** — arXiv, 공식 엔지니어링 블로그(Anthropic·OpenAI·DeepMind), NeurIPS/ICLR/ICML proceedings, 명망 있는 실무자 블로그. 출처 없는 통계는 쓰지 않습니다.
- **대안 패턴은 비교표로** — ReAct vs Reflexion vs Plan-Execute처럼 trade-off가 핵심인 주제는 표로 정리합니다.
- **모든 챕터에 시각 자료** — ASCII 다이어그램 / 비교표 / Mermaid 중 최소 하나로 루프 구조를 눈으로 보여줍니다.
- **코드 예시는 Python 중심** — 개념 이해용 의사 코드이며, 벤더 종속 패키지명은 실제와 다를 수 있음을 명시합니다.
