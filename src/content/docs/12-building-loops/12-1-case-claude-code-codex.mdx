## 이론에서 현실로

앞선 챕터들에서 루프의 구조, 패턴, 실패 모드를 이론적으로 다뤘다. 12절은 실전이다. 수백만 명이 매일 사용하는 두 코딩 에이전트 — Anthropic의 Claude Code와 OpenAI의 Codex — 가 실제로 루프를 어떻게 구현했는지 해부한다. 이 두 시스템은 서로 다른 설계 철학을 가지고 있으면서도, 동일한 핵심 문제들을 풀어야 했다.

Boris Cherny, Claude Code 책임자의 말을 다시 떠올려 보자.

> "나는 더 이상 Claude에 프롬프트하지 않는다. 루프를 돌리며 무엇을 할지 알아내게 한다. 내 일은 루프를 작성하는 것이다."

이 한 문장이 현대 코딩 에이전트의 철학을 담고 있다.

## Claude Code: 컨텍스트·행동·검증

Claude Code의 공식 가이드는 컨텍스트 수집·행동·결과 검증을 설명한다. 단계들은 섞이고 반복된다. 하니스는 도구를 제공하고 컨텍스트와 권한을 관리한다. 단순 질문에는 읽기만 필요할 수 있고, 버그 수정은 편집·테스트를 여러 번 반복할 수 있다.

```text
사용자의 목표와 제약
        |
        v
컨텍스트 구성 -> 모델이 행동 선택
        ^                |
        |                v
도구 결과 관찰 <- 인가 후 도구 실행
        |
        +-> 턴 종료 또는 다음 행동 요청
```

### 파일 기반 지침

`CLAUDE.md`는 프로젝트 지침을 저장한다. 모든 완료 행동을 기록하는 장부나 보안 경계는 아니다. 중요한 규칙은 이 파일에 두고 작업 진행 상태에는 현재 파일·증거로 이어지는 참조를 남긴다.

### Compaction과 컨텍스트 수명

Claude Code는 필요에 따라 오래된 도구 출력을 정리하고 대화를 요약한다. 현재 문서는 자동 압축 설정과 모델·설정별로 달라지는 임계치를 설명한다. 92%라는 고정값은 일반적인 제품 계약이 아니다. `/context`로 세션을 살피고 `/compact`로 보존할 내용을 지정한다.

### 서브에이전트와 공유 자원

서브에이전트는 별도 컨텍스트 창에서 작업하고 결과를 반환한다. 이 분리는 대화 길이를 줄일 뿐 파일 쓰기·네트워크·인증 정보를 격리하지 않는다. 파일 소유 범위를 배정하고 실행 권한은 별도로 강제한다.

## OpenAI Codex: Plan-Execute-Verify-Fix

2026년 1월 Codex 루프 글은 모델 추론과 도구 실행의 반복을 설명한다. 하니스가 프롬프트를 구성해 모델에 보내고, 요청된 도구를 실행한 뒤 결과를 돌려준다. 최종 assistant 메시지는 해당 턴을 끝낸다.

Plan-execute-verify-fix는 유용한 설계 패턴이지 제품이 강제하는 네 상태 머신이 아니다. 모델은 계획을 바꾸거나 편집 없이 조사할 수 있고, 예산 한도나 차단 사유를 보고할 수도 있다. 최종 응답만으로 테스트 통과를 증명할 수 없다.

```text
목표 -> 저장소 조사 -> 필요하면 계획
     -> 편집·도구 실행 -> 실제 결과 확인
     -> 수정 또는 차단 사유 보고 -> 증거 제시
```

### 학습 주장과 제품 역사의 구분

초기 2025년 클라우드 제품은 codex-1을 사용했다. 이 모델명은 릴리즈 이력이며 현재 제품 정의가 아니다. 테스트를 활용하도록 학습한 모델도 작업별 완료 판정 기준을 대신하지 못한다.

### 로컬과 클라우드 실행

Codex CLI는 로컬 저장소에서 동작하고, 호스팅된 클라우드 환경은 다른 실행 표면을 제공한다. 파일·네트워크·비밀·승인 정책은 환경마다 다르다. 컨테이너는 영향 범위를 줄이지만 허용된 외부 API의 부작용을 취소하거나 모든 탈출을 막아주지는 않는다.

요청한 검사가 실제 실행됐는지 확인한다. 작업 성공은 예산 소진·거부·인프라 실패와 구분한다. PR 생성·제출은 사용자의 요청과 권한에 따라 별도로 수행하는 행동이다.

## 두 시스템의 공통 원칙

| 설계 과제 | 실제 계약 |
|---|---|
| 완료 | 모델 턴 종료와 작업 성공 근거를 분리 |
| 컨텍스트 | 요약 이후에도 목표·현재 상태·출처 참조를 보존 |
| 격리 | 파일·네트워크·인증 정보 경계를 강제 |
| 검증 | 관련 테스트를 실행하고 실제 결과를 확인 |
| 외부 행동 | 공개·발송 등을 실행하기 전에 권한을 검사 |

이는 신뢰할 수 있는 루프의 설계 요구사항이다. 제품과 버전의 내부 구현이 같다는 뜻은 아니다. 다음 챕터에서는 SWE-agent의 ACI 설계를 살펴본다.
